# 停车场管理系统 (car-manage-web)

使用 Go 构建的停车场管理 Web 应用，提供车位增删改查、车位状态记录、费用规则配置以及入场/出场费用计算等完整功能。

## 功能特性

- **停车场管理**：创建/编辑/删除停车场，维护规划车位总数
- **车位管理**：车位的增删改查，实时状态（空闲 / 占用 / 维护中），可视化车位网格
- **车辆登记**：按车牌管理车辆信息（类型、颜色、车主、电话），支持按车牌自动去重
- **费用规则**：灵活的计费规则配置
  - 免费时长
  - 首段计费（时长 + 价格）
  - 后续单位计费（时长 + 价格，不足一单位按一单位算）
  - 每日封顶（跨日按自然日分别累计封顶）
  - 规则作用域：全局规则 / 单个停车场专属规则（专属优先）
- **入场 / 出场**：事务化处理，入场时自动绑定生效规则并占用车位，出场时计算费用并释放车位
- **费用预估**：在规则页实时预览任意时长下的费用
- **仪表盘**：停车场、车位、在场车辆、今日收入等统计数据

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.22+ | 使用 `net/http` 内置路由（方法 + 路径通配） |
| 数据库 | SQLite | 纯 Go 驱动 `modernc.org/sqlite`，无需 CGO |
| 前端 | 服务端渲染 HTML + 原生 JS | 模板与静态资源通过 `embed` 内嵌进二进制 |
| 架构 | 分层 | `models` / `store` / `fee` / `server` |

## 目录结构

```
car-manage-web/
├── cmd/carmanageweb/        # 程序入口（main + 演示数据 seed）
├── internal/
│   ├── models/              # 数据模型与可扫描的 Time 类型
│   ├── store/               # SQLite 数据访问层 + schema.sql
│   ├── fee/                 # 费用计算引擎（纯逻辑，无 IO 依赖）
│   └── server/              # HTTP 处理器、模板、静态资源
│       ├── templates/       # HTML 模板
│       └── static/          # CSS / JS
└── go.mod
```

## 快速开始

```bash
# 构建
go build -o carmanageweb ./cmd/carmanageweb

# 启动（写入演示数据：2 个停车场、若干车位、2 条费用规则）
./carmanageweb -addr :8080 -db parking.db -seed

# 浏览器访问
open http://localhost:8080
```

不使用 `-seed` 则启动空库，自行创建数据。数据库文件不存在会自动创建并建表。

## 命令行参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-addr` | `:8080` | HTTP 监听地址 |
| `-db` | `parking.db` | SQLite 数据库文件路径 |
| `-seed` | `false` | 首次启动时写入演示数据（数据库已有停车场时跳过） |

## 计费规则说明

一条费用规则包含以下参数：

| 字段 | 含义 |
|---|---|
| `free_minutes` | 免费时长（分钟），停车时长 ≤ 该值时免费 |
| `first_block_minutes` | 首段时长（分钟） |
| `first_block_price` | 首段价格 |
| `unit_minutes` | 后续计费单位时长（分钟） |
| `unit_price` | 后续单位价格（不足一个单位向上取整） |
| `daily_cap` | 每日封顶金额（0 表示不封顶），跨日按自然日分别累计 |

**计费示例**（默认规则：免费 15 分钟，首段 1 小时 10 元，之后每 30 分钟 5 元，日封顶 60 元）：

| 停车时长 | 费用 | 说明 |
|---|---|---|
| 10 分钟 | 0 元 | 在免费时长内 |
| 16 分钟 | 10 元 | 超免费，落首段 |
| 75 分钟 | 10 元 | 扣 15 免费 = 60，正好首段 |
| 120 分钟 | 20 元 | 首段 10 + 2 单位 × 5 |
| 5 小时 | 30 元 | 封顶 60 未触发 |

**规则解析优先级**：入场时优先匹配该停车场的专属启用规则，找不到则回退全局启用规则。

## 设计要点

- **费用引擎与存储解耦**：`fee.Calculator` 是纯函数式逻辑，仅依赖入参时间与规则，便于单测与复用；`store.CheckOut` 通过 `FeeCalculator` 回调在事务内调用引擎。
- **事务一致性**：入场/出场在单个数据库事务内完成车位状态与记录的更新，异常自动回滚。
- **规则快照**：入场时把生效规则 ID 绑定到停车记录，规则后续修改不影响已在场记录的结算（若规则被删除，结算时回退重新解析）。
- **时间存储**：SQLite 中时间以 RFC3339 字符串存储，`models.Time` 实现 `sql.Scanner` / `driver.Valuer` 自动转换，避免驱动类型不匹配。
